# 短信自动接收测试与排查

此功能订阅系统 `SMS_RECEIVED` 广播，使用 `RECEIVE_SMS` 权限处理新短信，不扫描历史收件箱。应用的“短信取件码自动识别”与对应取件/取餐识别开关必须开启。通知权限影响通知展示，需同时核对待取清单是否已有记录。

## 真实接收测试

打开一次应用，再回到桌面；用另一台手机发送普通 SMS：

`【圆通快递】凭7-3-4140到青禾村24排4号取尾号9528包裹。`

系统短信应用收到后，待取清单应新增取件码 `7-3-4140`，来源圆通，地址青禾村24排4号。运单尾号不应成为取件码。换一个测试码，在锁屏/后台再试一次。复制文本或 PROCESS_TEXT 只能验证文本识别路径，不能证明系统短信广播已经送达。

## ADB 排查

查看短信权限和 AppOps：`adb shell dumpsys package com.pickupcode.app`、`adb shell cmd appops get com.pickupcode.app RECEIVE_SMS`。

查看处理阶段：`adb logcat -s SmsReceiver`。日志记录收到广播、PDU 解析是否成功、消息分段数/长度、开关或噪声跳过、识别候选/过滤后数量、保存数量及8秒超时，不输出短信正文。

若本应用无接收日志，可检查 `adb shell dumpsys activity broadcasts` 中该短信的接收者记录，确认是否 `DELIVERED` 或 `SKIPPED` 及其 reason。不要将包含其他应用或用户短信信息的完整系统输出公开发布。

## 网络短信补充入口

用户随后报告卡2向卡1发送的消息于22:57收到，短信应用标记为“网络短信”。对应时间未发现新的系统 SMS 接收日志，因此普通 SMS 广播入口无法处理这次消息。

新增设置“短信通知识别（含网络短信）”，默认关闭。开启后按系统提示授权“取件码通知识别”的通知访问权限。短信开关只接受当前默认短信应用的新通知，微信通知由独立开关控制；忽略通知分组摘要，MessagingStyle 只取最新收到的一条消息，排除自己发送的消息。重复更新通过有限容量哈希缓存去重，落库继续使用原有上下文去重。微信入口与测试方法见 [微信通知说明](WECHAT_NOTIFICATIONS.md)。

此入口只进行本地取件/取餐识别，不调用在线 AI；不扫描历史通知或历史收件箱。没有正文、系统隐藏正文、短信应用正在当前会话而没有发通知等情况无法自动识别，仍可分享文本或截图。

授权后离开短信会话，回到桌面或码上闪记，重发一条带新测试码的网络短信，确认短信应用产生包含正文的通知，再检查待取清单。诊断日志使用 `adb logcat -s SmsNotificationListener SmsReceiver`。尚未授权和重发前，不将网络短信自动接收报告为通过。
