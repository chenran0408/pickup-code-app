# 短信数据集验证（2026-10-02）

用户提供 19 条通知，其中第 5、6 条为重复短信，第 13 条只包含运单号。人工真值为 17 个不同取件码，全部属于取件码，不能把电话、运单尾号、收费金额、柜号和格口号当成取件码。

公开回归样本对取件码、运单号、电话与地点进行同形态脱敏，保留分隔符、跨行、位数及模板。19 条样本在 `app/src/test/resources/corpus/sms-batch-*.txt`，逐码字段及拼接输入的测试在 `SmsBatchTest.kt`。

## 修复

- 无坐标短信及分享文本按通知的品牌标题隔离。单行粘贴多条短信时，每个码只使用本通知的地址、柜号和期限；截图继续使用卡片几何窗口。
- 明确取件码前缀支持两段式八位码 `dddd-dddd`，裸八位段式数字不自动召回。
- 同行地址支持“到…取尾号”“至…取件”“前往…取您的包裹”“已到…”；明确地址标签优先，保留更完整的门口描述，截掉通知文案。
- 品牌括号同时支持全角与归一化后的半角。同行承运商优先于站点名称，补充多多、邮侠、快宝站点来源。
- “免费存48小时”按记录时间加 48 小时计算免费保管期限；“请20:00前”按记录当日的本地时间计算。未给出期限的快递沿用默认 72 小时。

## 结果与边界

单条通知、分行拼接、整段拼接和归一化输入均通过码值、类型、来源、地址、柜号和期限断言。重复短信返回一个码，纯运单通知返回零码；格口号和裸段式八位数字的负向测试通过。

全量 JUnit 测试 271 项通过。识别语料 47/47，precision/recall 均为 1.0；Lint 无错误，Debug 和未签名 Release 构建通过。结果仅说明当前人工核对的语料通过，不代表所有短信模板均已覆盖。

本轮未配置或调用在线 AI、地图或物流服务进行验证。短信缺少原始接收时间，因此免费期限和钟点提醒只能以入库时间为基准；同一站点的不同地址简称仍保留原文，不自动合并为同一地点。

设备重新连接后，最新 arm64 测试包已通过 `adb install -r` 保留数据覆盖安装，安装返回 Success，应用主页正常启动。短信批次的字段验证在上述自动化回归中完成，没有将用户提供的真实取件凭证批量写入手机。
