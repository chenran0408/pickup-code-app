# 通知应用选择与侧边栏（开发分支）

## 操作

首页左上角菜单或横向滑动打开侧边栏。通知识别、识别偏好、识别方式与权限、AI 与辅助识别、自定义规则、常用取件地址、识别统计、重复记录、回收站、主题与显示及关于与反馈按类别进入。首页保留添加、分享和三个平台身份码直接入口，设置不再集中在一张长页面。

“通知识别”从本机应用列表勾选对象。支持名称/包名搜索、仅看已选、显示系统应用、刷新与清空搜索。默认显示用户应用及有桌面入口的系统应用；已选系统应用始终显示。卸载或不可见的已选应用也能取消选择。勾选即时保存，返回页面不会取消已提交的保存任务；列表不会因勾选而重排，方便连续操作。

## 数据与权限

首次使用新选择集合时，按原短信、微信、淘宝、拼多多、京东开关迁移；没有旧选择时不自动监听任何应用。保存空集合代表全部关闭，不再回退旧开关。默认短信选择保留动态语义，系统更换默认短信应用后随之匹配。

声明 QUERY_ALL_PACKAGES 以覆盖用户可任选的应用，包括无桌面入口的系统来源，应用列表仅在本机使用。固定包名/launcher queries 无法覆盖此范围。Manifest 只对该权限作 QueryAllPackagesPermission 的局部 lint 例外，其余检查保留；当前由 GitHub 分发。通知访问权限仍需系统授权，沿用原服务组件。应用启动时在后台检查已有选择和授权并请求重新绑定，处理部分系统覆盖安装后保留授权却未连接的问题。

通知接收先通过用户选择集合筛选，不为无关通知解密 AI/地图设置。排除本应用自己的通知与分组汇总，再沿用可见正文、验证码、金融噪音、身份码、类型、置信度与去重过滤。未知应用组合可见标题和正文；短信、微信保留最新收到正文语义。不会读取历史消息或调用在线 AI。

列表枚举在 IO 线程，筛选/排序在 Default 线程，图标仅对可见行异步读取，使用 64 个图标的缓存。UI 不显示包名匹配、上下文等内部规则说明。

## 验证

306 项 JVM 单测通过，47/47 语料通过。新增测试覆盖任意包名选择、旧配置迁移、清空不回退、默认短信切换、名称/包名搜索、系统应用、不可见应用取消选择和千条列表检索。Lint 与正式签名 R8 arm64 构建通过。最终包真机覆盖安装成功，确认侧边栏打开、应用列表授权、包名搜索、展开系统应用、勾选并返回后的持久保存，以及新版文案。原短信与微信选择保留。

当前设备系统保留通知授权，但服务没有出现在实际连接列表，启动重绑请求尚未使其恢复；用户已在系统页面重新开启授权，服务仍未出现在实际连接列表；需继续排查该设备的系统绑定限制。ADB 本地合成通知尚未成功入库，不将其计为端到端通过；微信及购物平台真实推送也未验证。测试用 Shell 选择已取消，保留原短信与微信选择，没有产生测试记录。
