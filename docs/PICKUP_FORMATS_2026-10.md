# 常见取件通知与粘贴导入适配（2026-10-12）

## 来源与范围

- [阿里云短信模板规范](https://help.aliyun.com/zh/sms/user-guide/create-message-templates-1/)：取件码变量支持 4～8 位数字、短横线和下划线的组合。这是短信平台规范，不代表所有驿站使用同一种编码。
- [腾讯云通知模板示例](https://cloud.tencent.com/document/product/382/39031)：快递通知使用“提货码”，同时单独列出登录验证码模板。不能因消息含“码”就收录。
- [丰巢官方取件说明](https://fcbox.com/pages/product/use.html)：短信、微信或支付宝通知中的取件码用于柜机取件；忘记码流程的手机验证码用途不同，继续保留验证码排除。
- 用户反馈的站点通知包含“凭字母数字分区码来取”。原“凭码”模式未覆盖“来取”，自动识别为空；添加页又只识别本应用的分享格式，将短信全文错误地送入裸码校验。

公开页面没有足够的频率统计，不能据此宣称已覆盖所有高频格式。此次以生产已有格式、用户反馈与官方公开规范为依据，公开回归全部使用合成码值、地点与时间。

## 调整

1. 凭码句式补充“来取、前往、扫码、自助取件”，保持完整字母数字码；沿用原边界、内容噪声及验证码过滤。
2. 明确码前缀补充“提货码、取件密码”；下划线的两段、三段与四位加四位组合通过强前缀/凭码句式识别，保留真实分隔符。内容噪声检查先移除下划线，防止全零/全一绕过。
3. 规则页面从同一生产定义生成，更新“前缀取码”和“凭码取件”名称，不增加重复的隐藏规则。
4. 单码仍可直接添加。粘贴短信或多条取件通知，以及点击“导入剪贴板”，复用生产提取器，显示码值、类型、来源和地址预览，确认才入库；本应用分享格式保留严格条数校验。
5. 通知解析在后台线程执行；输入变化后旧预览即失效，防止确认旧内容。长度上限 30000、单次上限 300、重复活跃记录仍由既有入库流程跳过。

## 回归范围

矩阵包含三段/四段货架码、字母前缀分段、字母数字分区码、两段数字、4～8 位数字、四位加四位柜码与下划线形式。覆盖来取、扫码、前往、领取、取货、两种新增前缀、大小写和全角横杠。导入用例覆盖短信全文、地址、混合多条通知、重复消息、验证码、只有配送信息、金融信息、原分享格式、文本长度及裸码入口。

修复前新增两条来取用例均失败，负向用例通过。修复后完整 353 项单测、48/48 识别语料通过，Lint 与正式签名 arm64 构建结果记录在 PR 中。未将本次开发修复改称已发布版本，未修改 v1.3.0 标签或已发布 APK。

## 真机验证（2026-10-12）

正式签名修复包已覆盖安装并可正常启动。用户手动复制粘贴合成通知，随后通过应用界面核对：

- “凭字母数字分区码来取”全文进入预览，完整码值、取件类型、顺丰来源与站点地址正确，确认后保存一条。
- “导入剪贴板”能再次预览相同正文；重复确认后仍只有一条活跃记录。
- 单个字母数字分区码直接录入并保存成功，没有被通知导入模式挤走。
- 包含登录验证码的消息显示“未找到取件码或取餐码”，确认按钮禁用，没有新增记录。
- 本轮两条合成记录已从主页删除，并在回收站逐条彻底删除；未清空整个数据库或其他记录。未发现本轮操作的应用崩溃日志。
