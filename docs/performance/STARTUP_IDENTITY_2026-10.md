# 启动与身份码跳转优化验证（2026-10）

本轮改动把三个通知渠道合并为一次系统调用，避免 Activity 启动时重复读取无障碍状态，并把截图维护延后 2 秒，减少与首页首次读库争用。淘宝、菜鸟、拼多多入口现在先发送限定包名的深链；只有跳转失败时才查询安装状态并尝试原有降级入口。

## 同机启动对照

在同一台 arm64 手机上交替覆盖安装旧版与新版正式签名 Release APK，不清除应用数据。每轮连续执行 5 次 `am force-stop` 后 `am start -W`，记录 `TotalTime`（毫秒）：

| 顺序 | 版本 | 5 次 TotalTime（ms） |
|---|---|---|
| 1 | 旧版 | 508、175、123、118、124 |
| 2 | 新版 | 189、184、113、120、110 |
| 3 | 旧版 | 178、153、103、139、116 |
| 4 | 新版 | 171、196、105、109、106 |

合并两轮后的中位数：旧版约 132ms，新版约 117ms。覆盖安装后的首次启动波动明显；这组数据只说明新路径没有启动回退，不能证明稳定的 15ms 提速。`am start -W` 也不代表记录列表全部加载完成。

最终构建保留加密迁移的即时执行，仅延后截图清理；覆盖安装后再测 5 次为 115、105、121、109、114ms（中位数 114ms），与上表新版处于相近范围。

## 跳转核对

- 淘宝与拼多多已安装：从首页底栏点击后，系统前台 Activity 分别进入目标应用。
- 菜鸟未安装：点击后仍留在本应用，按现有文案提示未安装。该设备无法验证菜鸟页面实际加载耗时。
- 外部应用的网络、登录和页面渲染由目标应用控制，本轮优化只减少本应用发送深链前的同步工作，不宣称外部页面端到端加速。

本轮 297 项单元测试、47/47 识别语料与签名 Release 构建通过。
