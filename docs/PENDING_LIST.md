# 记录列表与识别修复

## 使用

主页标题栏下方固定「淘宝码」「菜鸟码」「拼多多码」三个大按钮，每个入口最小高度 88dp，直接发起对应平台跳转，省去应用内选择页；详情页提供同样的三个按钮。未安装的平台会给出提示，系统可能要求确认跨应用跳转。
1.2.0 按用户反馈移除独立待取清单与待取筛选。主页默认显示全部记录（含券码和已取历史），保留已取/过期、类型筛选和地址分组。
点击「本站已取」会确认本组可见活跃记录的数量，再一次归档；提示条可撤销本次操作。
未填地址的记录独立显示，不提供整组归档，避免把不同地点的记录误当成一个站点。
「全部记录」包含券码；类型筛选、按时间/按地址切换继续可用。

## 识别与数据保护

- 多码页面逐码隔离地址、预存地址匹配、柜号、期限和运单文本；位置不确定的行不强行分配。
- 地图按每条记录的当前地址验证，带条件 SQL 拒绝过时的异步回填；物流补全只作用于本次记录且地址仍为空时。
- 合并需要订单/运单或地点与时间等上下文。相同品牌、裸短码和信息不足不能直接证明属于同一单。
- 编辑、确认的字段保存在数据库保护位中；升级前的确认状态在识别回填时转入保护位。
- 地址修改会清除旧地图验证；AI 不同地址保存为候选，可在详情页确认使用。
- 本地先保存、通知，AI 后台补充。已归档或修改码值的本次记录拒绝旧任务更新。
- HTTP 取消主动断开连接；短信广播仅等待本地处理。
- 单条已取、提醒和新通知按记录 ID 区分，避免影响不同地点的同码。
- 截图删除检查全部记录（含回收站）引用，并保护正在处理的 AI 任务使用的图片。
- 批量撤销按原 ID 和本次归档时间恢复，不恢复其他批次、不影响后来新增的记录。

## 数据库

数据库版本从 7 升为 9，增加 trackingNumber、userEditedFields、recognitionOrigin、addressOrigin、suggestedAddress。
8→9 增加 archiveKind，区分已取历史与回收站；旧归档记录不猜测用途，保留原回收站行为。
7→8、8→9 使用 ALTER TABLE 保留旧数据，现有迁移链继续使用，不采用破坏性迁移。
